状态：**G0-G3 首批功能与 N0-N3 纯 Java 原型实施中**。设计依据见

本计划不替代当前 NeoForge Alpha 的 M5 验收；M5 未完成项仍见
[NeoForge 阶段计划](next-phase-neoforge-1.21.1.md)。每一阶段单独评审后再进入下一阶段。

| N2 跨维度与交通 | 实测传送边、冰道船/水路船/铁路模式、设施状态、速度/玩家能力约束 | 多维度换乘与单维度步行竞争时选择较低有效代价；设施关闭或无载具时不会选不可用边；地图显示分段路线 |
| N3 学习与准备任务 | 轨迹证据、速度校准、可选载具取用/合成前置 DAG、统一预留 | 无轨迹仍可发现新路；循环依赖停止并解释；需求与材料不双重占用；前置任务须玩家确认 |

截至 2026-09-25：G0/G1 的聚合、数量编辑、显示设置和入口已实现；G2 的精确 variant
会话需求、来源槽位分配与缺货报告已实现。G3.1 已把原局部 Y 投影视图升级为 Ponder 风格的
真实方块 3D 容器场景，并在 2D 近距离显示容器方块图标。G3.2 已增加独立只读内容页，展示
原槽位、精确数量、variant 摘要和快照时间，并支持逐层进入已记录的嵌套容器。
N0/N1 的独立 `navigation-core`、有界已知通行连接缓存、A*/Dijkstra 和独立航点接口已有测试；
N2 的交通模式/显式跨维度边与 N3 的轨迹时间证据/前置任务 DAG 为纯 Java 原型。地图通过可选
`NavigationGateway` 接受外部路线，但目前无 provider；游戏世界观测、交通设施发现、轨迹采集与
持久化、来源账本与前置任务账本的跨模块整合、实机视觉/交互验收仍待完成。现有会话计划不是
可自动执行的取物流程。

## 实施顺序与决策门

1. 当前 M5 的剩余兼容与打包验收继续独立推进；G0/G1 代码通过构建不等于 Alpha 实机验收完成。
2. G0 → G1 → G2 提供可独立使用的库存工作流；G3 提供无需导航也有价值的容器空间浏览。
3. N0 在 G3 接入点稳定时启动。N1 是导航最小可用证明；N2/N3 在观察数据、性能和用户交互
   验证后推进。N4 为后续扩展，不阻塞基础 GUI 发布。
4. 每阶段保持 `core` 无 Minecraft/Loader 导入、现有 `gradlew check` 通过。导航独立构建和
   LItemFinder 无导航构建都必须在 CI 中验证；实际路线渲染另做游戏内验收。

## G3.2.1 实机反馈修复批次

状态：**代码与自动化回归已完成；等待打包客户端视觉复测。**

1. **[x] P0 — 旧快照页面崩溃。** 2026-09-25 13:08 的最新报告显示，
   `ContainerContentsScreen` 把 `Instant` 直接传入 `Component.translatable`，违反 Minecraft 翻译参数
   只接受 `Component/Number/Boolean/String` 的约束。改为共享的快照时间文本格式化器，并同时修复
   `AcquisitionPlanScreen` 中相同写法，避免第二个同源崩溃点。回归验证须分别打开新鲜/过期的根容器、
   嵌套容器和获取计划，并在 `zh_cn/en_us` 下运行。
2. **[x] P1 — 2D 坐标缺失。** 网格的每条主线显示 X 或 Z 刻度，使用现有稳定网格步长；标签在地图边缘
   带低对比背景并做碰撞跳过。鼠标位于地图内时另显示光标对应的 `X/Z`，选中容器仍在详情区显示
   完整 `X/Y/Z`。平移、滚轮锚点缩放、负坐标和大坐标下刻度必须稳定且不盖住顶部控件。
3. **[x] P1 — 点位独立显示。** 容器标记不再按距离或相同 `X/Z` 自动聚合，也不显示合并数量；远景使用
   独立简化方块，近景逐个显示容器图标。投影范围重叠时连续点击在候选容器之间切换，避免某个容器
   永久无法选择。
4. **[x] P1 — 3D 容器框线。** 删除局部 3D 场景中围绕容器中心绘制的屏幕二维方框；参考 Meteor
   `Renderer3D.boxLines` 的 8 顶点、12 边做法，改用 `LevelRenderer.renderLineBox` 在容器方块模型相同的
   轨道相机变换和深度缓冲中绘制单位方块线框。选中、搜索命中和计划来源继续使用不同颜色；点击范围
   改由 8 个立方体角点的屏幕投影包围框计算，旋转和缩放后仍与可见线框对齐。
5. **[x] P1 — 停靠顺序与过期提示。** 原地图按物品/快照分配顺序连接来源，不能代表最短顺序；改为从
   玩家当前位置出发，对同 scope、同维度且不超过 15 个的停靠点求精确最短开放路径，较大计划使用
   确定性的最近邻加 2-opt，并让示意线和可选导航请求共用结果。没有导航 provider 时仍明确标为直线
   距离示意，不声称可步行。获取计划不再为每个旧来源增加“快照可能过期”文本行，改为来源行右侧的
   小型感叹号，悬停时才显示观测时间。
6. **[ ] 实机验收门。** `gradlew clean check` 和发布 JAR 校验已通过；打包客户端仍需依次复测内容页、获取计划、
   2D 坐标与独立点位；本批次不修改索引 schema 或容器身份。实机录屏/截图确认 5 倍 GUI 缩放下文本、
   坐标、标记和 3D 框线仍可读。

## G3.3 地图性能与路线过渡

状态：**2026-10-20 按实机反馈移除地形叠加及采样，保留玩家指针；等待性能复测。**

1. **[x] 移除地形采样。** 删除水域、岩浆、地形底色、等高线及其采样器，不再逐帧查询高度图、
   流体和构造地形采样数组。保留坐标网格、容器点位和路线。
2. **[x] 降低重复计算。** 容器按维度分组和排序只在快照变化后更新；2D 图标使用静态缓存；3D
   先剔除屏外容器再绘制，方块状态低频刷新；空需求跳过库存搜索，未变化的计划和停靠点不重复
   分配或求最短顺序。路线先裁剪到视口，避免绘制屏外点，也避免原先 4096 像素上限截断可见路线。
3. **[x] 玩家位置。** 删除白色方框，改为使用实时坐标和朝向旋转的原版青色地图指针；路线首段使用实时
   玩家位置，停靠顺序仍按低频刷新，避免每帧重算最短路。
4. **[ ] 路线过渡。** 玩家移动、停靠顺序重算或 provider 返回新路径时，在旧/新路线的公共起点附近
   做短时间位置插值；路径形状变化过大时淡出再淡入，避免把不相干的折线直接拉伸。
5. **[ ] Baritone 适配评估。** 以 `E:/projects/tools/working/baritone` 的 `origin/1.21.1` 分支为参考，复用其
   A* 移动代价、可达目标和路径折线压缩思路；适配器保持只读计算，不启动自动行走，并作为可选独立
   provider 交付。未安装 provider 时继续使用直线距离停靠顺序，不把示意线描述为实际路线。
