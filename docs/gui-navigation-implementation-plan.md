独立/联装运行和摘要原生渲染探针已通过；真实世界路线待验收，N2/N3 仍为纯 Java 原型。**

## 实施顺序与决策门

1. 先完成当前 beta 的采集、界面与性能复测；原 M5 剩余项纳入统一 TODO。代码通过构建不等于实机验收完成。
2. G0 → G1 → G2 提供可独立使用的库存工作流；G3 提供无需导航也有价值的容器空间浏览。
3. B1、I3/I4 的独立/联装探针及边界回归、I5 的摘要/详情和原生渲染夹具已完成；继续真实世界
   验收（V7）。N2/N3 游戏集成在观察数据、性能和用户交互验证后推进；N4 为后续扩展。
4. 每阶段保持 `core` 无 Minecraft/Loader 导入、现有 `gradlew check` 通过。导航独立构建和
   LItemFinder 无导航构建都必须在 CI 中验证；实际路线渲染另做游戏内验收。

## G3.2.1 实机反馈修复批次

状态：**代码与自动化回归已完成；等待打包客户端视觉复测。**

1. **[x] P0 — 旧快照页面崩溃。** 2026-09-25 13:08 的最新报告显示，
   `ContainerContentsScreen` 把 `Instant` 直接传入 `Component.translatable`，违反 Minecraft 翻译参数
   只接受 `Component/Number/Boolean/String` 的约束。改为共享的快照时间文本格式化器，并同时修复
   `AcquisitionPlanScreen` 中相同写法，避免第二个同源崩溃点。回归验证须分别打开新鲜/过期的根容器、
   嵌套容器和获取计划，并在 `zh_cn/en_us` 下运行。
2. **[x] P1 — 2D 坐标缺失。** 网格的每条主线显示 X 或 Z 刻度，使用现有稳定网格步长；标签在地图边缘
   带低对比背景并做碰撞跳过。鼠标位于地图内时另显示光标对应的 `X/Z`，选中容器仍在详情区显示
   完整 `X/Y/Z`。平移、滚轮锚点缩放、负坐标和大坐标下刻度必须稳定且不盖住顶部控件。

   独立简化方块，近景逐个显示容器图标。投影范围重叠时连续点击在候选容器之间切换，避免某个容器
   永久无法选择。
4. **[x] P1 — 3D 容器框线。** 删除局部 3D 场景中围绕容器中心绘制的屏幕二维方框；参考 Meteor
   `Renderer3D.boxLines` 的 8 顶点、12 边做法，改用 `LevelRenderer.renderLineBox` 在容器方块模型相同的
   轨道相机变换和深度缓冲中绘制单位方块线框。选中、搜索命中和计划来源继续使用不同颜色；点击范围
   改由 8 个立方体角点的屏幕投影包围框计算，旋转和缩放后仍与可见线框对齐。
5. **[x] P1 — 停靠顺序与过期提示。** 原地图按物品/快照分配顺序连接来源，不能代表最短顺序；改为从
   玩家当前位置出发，对同 scope、同维度且不超过 15 个的停靠点求精确最短开放路径，较大计划使用
   确定性的最近邻加 2-opt，并让示意线和可选导航请求共用结果。没有导航 provider 时仍明确标为直线
   距离示意，不声称可步行。获取计划不再为每个旧来源增加“快照可能过期”文本行，改为来源行右侧的
   小型感叹号，悬停时才显示观测时间。

## G3.3 地图性能与路线过渡

状态：**已移除地形叠加及采样，保留玩家指针；路线过渡实现及自动化完成，视觉与性能待复测。**
截至 2026-10-28，实现与验证依据见[本批记录](validation/map-transition-plugin-runtime-2026-10-28.md)，
剩余工作统一跟踪于[开发状态与 TODO](development-status.md) V4/V5、V7；I5 已补齐实现与原生渲染夹具。

1. **[x] 移除地形采样。** 删除水域、岩浆、地形底色、等高线及其采样器，不再逐帧查询高度图、
   流体和构造地形采样数组。保留坐标网格、容器点位和路线。
2. **[x] 降低重复计算。** 容器按维度分组和排序只在快照变化后更新；2D 图标使用静态缓存；3D
   先剔除屏外容器再绘制，方块状态低频刷新；空需求跳过库存搜索，未变化的计划和停靠点不重复
   分配或求最短顺序。路线先裁剪到视口，避免绘制屏外点，也避免原先 4096 像素上限截断可见路线。
3. **[x] 玩家位置。** 删除白色方框，改为使用实时坐标和朝向旋转的原版青色地图指针；路线首段使用实时
   玩家位置，停靠顺序仍按低频刷新，避免每帧重算最短路。
4. **[x] 路线过渡实现与自动化（I1）。** 玩家移动使用原版渲染插值；旧/新路线共同锚点前的
   短前缀做 240 ms 插值，停靠重排、路径形状或来源类型变化时淡出再淡入。频繁更新从已经显示的
   状态继续，跨世界/起始维度或清空需求时重置。2D/3D 共用帧数据，实机视觉仍由 V4/V5 验收。
5. **实现与自动化完成、待实机：只读步行导航（I3/I4）。** 已有碰撞步行、普通航点/容器邻接目标、
   路径压缩与游戏侧 provider；[Baritone 方案评估](navigation.md)和独立/联装启动验证已补齐。
   I5 已补齐路线摘要、缺口和证据详情；中英文 GUI 3/5 倍渲染夹具通过，真实世界效果由 V7 验收。
   适配器不启动自动行走；未安装 provider 时继续
   使用直线距离停靠顺序，不把示意线描述为实际路线。
