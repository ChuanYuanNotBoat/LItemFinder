状态：**G0-G3 首批功能与 N0-N3 纯 Java 原型实施中**。设计依据见
[GUI 与导航架构](gui-navigation-architecture.md)。
本计划不替代当前 NeoForge Alpha 的 M5 验收；M5 未完成项仍见
[NeoForge 阶段计划](next-phase-neoforge-1.21.1.md)。每一阶段单独评审后再进入下一阶段。

截至 2026-09-23：G0/G1 的聚合、数量编辑、显示设置和入口已实现；G2 的精确 variant
会话需求、来源槽位分配与缺货报告，以及 G3 的全屏坐标地图和局部 Y 投影视图已实现首批。
N0/N1 的独立 `navigation-core`、有界已知通行连接缓存、A*/Dijkstra 和独立航点接口已有测试；
N2 的交通模式/显式跨维度边与 N3 的轨迹时间证据/前置任务 DAG 为纯 Java 原型。地图通过可选
`NavigationGateway` 接受外部路线，但目前无 provider；游戏世界观测、交通设施发现、轨迹采集与
持久化、来源账本与前置任务账本的跨模块整合、实机视觉/交互验收仍待完成。现有会话计划不是
可自动执行的取物流程。

## 实施顺序与决策门

1. 当前 M5 的剩余兼容与打包验收继续独立推进；G0/G1 代码通过构建不等于 Alpha 实机验收完成。
2. G0 → G1 → G2 提供可独立使用的库存工作流；G3 提供无需导航也有价值的容器空间浏览。
3. N0 在 G3 接入点稳定时启动。N1 是导航最小可用证明；N2/N3 在观察数据、性能和用户交互
   验证后推进。N4 为后续扩展，不阻塞基础 GUI 发布。
4. 每阶段保持 `core` 无 Minecraft/Loader 导入、现有 `gradlew check` 通过。导航独立构建和
   LItemFinder 无导航构建都必须在 CI 中验证；实际路线渲染另做游戏内验收。
